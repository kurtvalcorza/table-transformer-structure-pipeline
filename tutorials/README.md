## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`, detection obligations) recognised the structure of a table rendered in code and reported per-label `box_iou` against its drawn rows and columns as sanity evidence. This notebook keeps the inference contract as Section 5 — on a real SciTSR-PD table with reference boxes, so the header labels the checkpoint emits and the corpus does not carry are visible — and adds the adaptation contract around it: an embedded public-domain corpus whose boxes are a stated derivation, per-label AP / class means / grid agreement in the carried `metrics.py` with a grid prior and the zero-shot checkpoint as reference points, a three-policy ladder (the checkpoint's rows copied into restricted heads and left untrained, the heads trained, a bounded decoder unfreeze) under the DETR set loss with an exact Hungarian matcher implemented in the carried module, selected on validation, before/after structure, and an artifact that reloads. `evaluate` is the labelled corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 4 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports) — the 94 base64 PNGs and their derived boxes travel inside the carried `sample_data.py` — Section 3 carries the 4-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision; `verify_snapshot` re-hashes every entry; `TableTransformerStructurePipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads with `local_files_only=True`, `trust_remote_code=False` and `use_pretrained_backbone=False`; no cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors`, `urllib`, `scipy`, `base64`, the model, the processor or the decoder outputs directly.
- **Data (DAT1–DAT9, ST6):** the default sample is embedded — 94 PNGs (0.9 MB) with one SHA-256 each, from `bevaya/SciTSR-pd` at commit `dae336ef` (two parquet files pinned by SHA-256), CC0 / public-domain source papers — each refused on any mismatch before it is decoded, and drawn by a seeded shuffle of whole papers into 21 / 23 / 50 test, validation and training tables (`check_split_disjoint` asserts no shared table by decoded-pixel digest and no shared paper; `split_summary` reports tables, objects per label and papers per split). The structure boxes are a stated derivation from the dataset's cells, documented in the carried module and in `docs/WEIGHTS.md`. The template's *External access* bullet says the default path fetches nothing beyond the Hub.
- **Stages (§4.1):** `load_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `check_split_disjoint` + `split_summary` + refusal probes (validation, with three digests) → `validate_inputs` + `pipe.recognize` with sanity checks + `structure_summary` + `evaluation_report` against the table's reference boxes (inference contract, `sample-sanity`) → `prior_baseline` + `pipe.evaluate_zero_shot` + `pipe.adapt(trainable_layers=0)` + `pipe.evaluate` (prior, zero-shot row, copied-head zero-shot policy vs frozen policy) → `pipe.adapt(trainable_layers=TRAINABLE_LAYERS)` (the full ladder, selected on validation) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `pipe.recognize_adapted` before (a fresh pipeline with heads trained the same way) and after, with `recognize` beside them (inference) → `pipe.save_artifact` → `TableTransformerStructurePipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** every box is xyxy in input pixels; AP is computed over every (query, class) pair and is threshold-free, the per-label recall at 0.5 (the base `RECOGNITION_THRESHOLD`) and grid agreement are reported beside it and the notebook states that the adapted classes need their own operating point; the restricted head's softmax is a ranking signal under a 0.1 no-object weight, not a calibrated confidence; no acceptance threshold ships.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the grid prior, the zero-shot checkpoint and the frozen policy are scored on the same 21 test tables as the selected policy, per-image rows are printed beside every mean, the selection rule is stated (lowest validation set loss, the checkpoint's own rows and the heads competing) and the notebook asserts only that the heads and the selected model beat the prior — a gain over the heads or the checkpoint is the question, not an assertion; the notebook says in the closing that the selection criterion and the headline metric disagree on this corpus; every metric is labelled as one seeded split of one small corpus with no dispersion estimate (one table ≈ five points of grid agreement).
- **Split integrity (SPL1–SPL8):** the split is seeded, drawn by whole papers and table-disjoint by decoded-pixel digest; validation selects the epoch and policy and the test split is used for nothing but the final evaluation, the before/after render and the reload-parity check; the notebook states that real data must be split by paper, document or source.
- **Ceilings (VAL6):** `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4,096), `MAX_DETECTIONS` (125), `NUM_QUERIES` (125), `D_MODEL` (256), `DECODER_LAYERS` (6), the record bounds (8..2,000), the object bounds (1..125 per table, ≥ 2 px sides, four labels, one `table`, at least one row and one column) and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one threshold refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user tables flow through the same validation, seeded group-disjoint split (the loader refuses a `structure.csv` row without a non-empty `group` and rows of one `id` that disagree on `file` or `group`, so the group-disjoint guarantee holds for BYOD as it does for the sample; `require_group=False` is the explicit opt-out), prior, zero-shot scoring, the ladder, evaluation, rendering, export and reload cells; images inside the uploaded zip are decoded from the archive, never extracted. The expected schema and the privacy guidance are stated in the Prerequisites and in Section 4, and the training structure table is written to `outputs/table_transformer_structure_train.csv` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
